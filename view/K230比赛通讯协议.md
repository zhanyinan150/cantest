# K230 比赛视觉系统 - 通讯协议与工作流程

## 文件

| 文件 | 说明 |
|------|------|
| `view/k230_competition.py` | K230 端比赛主程序（从机） |
| `modules/action/action.c` | STM32 端比赛动作序列（主机） |
| `modules/k230/K230.c` | STM32 端通讯驱动 |
| `modules/k230/K230.h` | STM32 端通讯接口定义 |

## 硬件连接

| K230 | STM32 | 说明 |
|------|-------|------|
| UART3 TX (Pin 50) | USART3 RX (PB11) | K230 -> STM32 |
| UART3 RX (Pin 51) | USART3 TX (PB10) | STM32 -> K230 |

- 波特率: 115200, 8N1
- STM32 接收: DMA 方式, 8 字节定长, 中断回调解析
- K230 接收: `uart.any() >= 8` 检查后 `uart.read(8)` 读取, 避免半帧
- 帧格式: 8 字节定长帧, byte[7] = XOR(byte[0..6])

## 通讯架构: STM32 主机 / K230 从机

- **STM32 为通讯主机**, 每个阶段由 STM32 主动发命令启动
- **K230 为通讯从机**, 收到命令后才开始识别
- **每步都有应答**: STM32 发命令 -> K230 回 ACK -> K230 发数据 -> STM32 回 ACK

## 模型与摄像头

- **单模型**: `best.kmodel`（8 类: `1, 2, 3, 4, 5, g, w, y`），三个阶段共用
- 数字类别索引 0-4，豆子类别索引 5-7
- K230 收到命令后才开摄像头, 识别完收到 ACK 后关摄像头

| 阶段 | STM32 命令 | 摄像头 | 识别目标 | 过滤类别索引 |
|------|-----------|--------|----------|-------------|
| Phase 1 | 0x02 LOOK_BEAN | cam 2 | 3 颗豆子（左->右） | 5-7 (g, w, y) |
| Phase 2 | 0x03 LOOK_NUMBER | cam 1 | 正面 3 个数字（左->右） | 0-4 (1-5) |
| Phase 3 | 0x01 LOOK_SIDE | cam 0 | 侧面 1 个数字 | 0-4 (1-5) |

## 帧类型定义

### byte[1] = 阶段号

`byte[1]` 承载**阶段号**，所有帧都带（就绪帧 `0x0B` 除外，固定 0）：

| 值 | 阶段 |
|---|---|
| 0 | 不属于任何阶段（就绪帧 / 未升级的旧脚本） |
| 1 | Phase1 豆子识别 |
| 2 | Phase2 正面数字 |
| 3 | Phase3 侧面数字 |

收到的帧若 `byte[1]` 与本端当前阶段不符，**原地丢弃**。最要命的是 `0x0A` ——
`k230_ack_flag` 是累加计数器，上一阶段迟到的 ACK 会被下一阶段白白消费，主机
以为对端应答了而实际没有，从此步步错位。

> `byte[1] == 0` 一律放行：未升级的 K230 脚本 `byte[1]` 恒为 0，此时退化成升级前
> 的行为（不校验），保证新固件配旧脚本也能跑，不会因协议不匹配直接锁死。

### STM32 -> K230

| byte[0] | byte[1] | 含义 |
|---------|---------|------|
| 0x02 | 阶段号 | 启动豆子识别 (LOOK_BEAN) |
| 0x03 | 阶段号 | 启动正面数字识别 (LOOK_NUMBER) |
| 0x01 | 阶段号 | 启动侧面数字识别 (LOOK_SIDE) |
| 0x06 | 阶段号 | **数据已收到，关摄像头进下一阶段** (CLOSE) |
| **0x0C** | 阶段号 | **重发上一次回复** (RESYNC)，不改变任一端的阶段 |

**`0x06` 与 `0x0C` 必须分开。** 早先主机在数据超时时拿 `0x06` 兼作重同步信号，
而 `0x06` 的正常含义是「进下一阶段」—— K230 收到就真的关摄像头前进了，可主机
其实还在重试本阶段，两端从此错开一个阶段。现在超时走 `0x0C`：K230 把上次那帧
再发一遍，谁的阶段都不动。只有 `0x0C` 也无果时，主机才退回重发整条命令
（贵：K230 要重开摄像头重跑一次 20s 识别）。

### K230 -> STM32

| byte[0] | byte[1] | byte[2..6] | 含义 | STM32 flag |
|---------|---------|------------|------|------------|
| 0x0A | 阶段号 | 0x00 × 5 | K230 应答帧 (命令收到 / 识别完成) | k230_ack_flag++ |
| 0x0B | **0** | 0x00 × 5 | 就绪/心跳帧 | k230_ready_flag=1 |
| 0x02 | 阶段号 | b1, b2, b3, 0x00, 0x00 | 豆子颜色帧（左->右） | bean_flag=1 |
| 0x01 | 阶段号 | n1, n2, n3, n4, n5 | 完整 5 数字帧（左->右） | full_number_flag=1 |

> 所有帧 byte[7] = byte[0] ^ byte[1] ^ ... ^ byte[6]

## 超时设置

| 等待项 | STM32 (主机) | K230 (从机) | 超时行为 |
|--------|-------------|-------------|---------|
| 就绪帧 (0x0B) | 30s | - | 放行, 继续往下跑 |
| 命令 ACK (0x0A) | 3s | - | 重发命令, 最多 3 轮 |
| 数据帧 / 识别完成 ACK | **25s** | - | 发 **RESYNC(0x0C)** 要重传 |
| RESYNC 后等重传 | **3s** | - | 无果则重发整条命令, 最多 3 轮 |
| 对端静默示警 | 3s | - | 只打印 `[WARN] K230 silent Xms`, 不改流程 |
| STM32 命令 | - | **无限等 + 心跳** | 每 300ms 发一个 0x0B |
| STM32 ACK (0x06) | - | 10s | 只打印, 继续往下 |
| 识别循环 | - | 20s | 返回 best_effort 兜底 |

两条约束必须成立，否则两端会错开阶段：

1. **STM32 数据超时 (25s) > K230 识别超时 (20s)**。反过来的话，K230 还在识别循环里
   没出结果，主机已判超时并发 CLOSE 重同步 + 重发命令；K230 识别完发出的是数据帧而
   不是 ACK，主机不认继续等到 ACK 超时，而 K230 转去等 CLOSE 时正好读到主机重同步
   发的那个 0x06，误判本阶段成功进入下一阶段。
2. **K230 等命令不设上限**。主机在 P1→P2 之间要跑完抓豆(约38s)+越障(约12s)共 50s
   左右，P2→P3 之间还有一段行程。K230 端原来是 30s 到点 `raise Exception`，会把整个
   脚本带走，之后 P2/P3 必然零应答。比赛节奏由主机主导，从机不能自行判超时退出。

## 完整工作流程

### Phase 1: 豆子识别

```
STM32 (主机)                         K230 (从机)
  |                                    |
  | 发送 0x02 01 00 00 00 00 00 XOR -->|  等待 LOOK_BEAN 命令
  |                                    |  收到命令
  | <-- 0x0A 00 00 00 00 00 00 XOR --- |  发送 ACK
  | 等 k230_ack_flag (3s超时)           |
  |                                    |  开 cam2, 识别豆子(左->右)
  |                                    |  防抖 3 帧确认
  | <-- 0x02 00 b1 b2 b3 00 00 XOR --- |  发送豆子数据
  | 等 bean_flag (25s超时)              |  bean_flag=1, bean_locked=1
  | 发送 0x06 00 00 00 00 00 00 XOR -->|  等待 ACK (10s超时)
  |                                    |  关闭 cam2
  |                                    |
  | action_douzi_first() 电机抓豆子     |
```

### Phase 2: 正面数字识别

```
STM32 (主机)                         K230 (从机)
  |                                    |
  | 电机移动: 障碍物避让 x2             |  等待 LOOK_NUMBER 命令
  |                                    |
  | 发送 0x03 01 00 00 00 00 00 XOR -->|  收到命令
  | <-- 0x0A 00 00 00 00 00 00 XOR --- |  发送 ACK (命令收到)
  | 等 k230_ack_flag (3s超时)           |
  |                                    |  开 cam1, 识别正面数字(左->右)
  |                                    |  防抖 3 帧确认, 内部存储
  | <-- 0x0A 00 00 00 00 00 00 XOR --- |  发送 ACK (识别完成)
  | 等 k230_ack_flag (25s超时)          |  (不发数据帧, 正面数字仅 K230 内部使用)
  | 发送 0x06 00 00 00 00 00 00 XOR -->|  等待 ACK (10s超时)
  |                                    |  关闭 cam1
```

### Phase 3: 侧面数字识别 + 推理第 5 个数字

```
STM32 (主机)                         K230 (从机)
  |                                    |
  | 电机移动: 到箱子                    |  等待 LOOK_SIDE 命令
  |                                    |
  | 发送 0x01 01 00 00 00 00 00 XOR -->|  收到命令
  | <-- 0x0A 00 00 00 00 00 00 XOR --- |  发送 ACK
  | 等 k230_ack_flag (3s超时)           |
  |                                    |  开 cam0, 识别侧面 1 个数字
  |                                    |  防抖 3 帧确认
  |                                    |  推理第 5 个数字
  |                                    |  组合: [侧面, 正1, 正2, 正3, 推理]
  | <-- 0x01 00 n1 n2 n3 n4 n5 XOR --- |  发送完整 5 数字
  | 等 full_number_flag (25s超时)       |  full_number_flag=1
  | 发送 0x06 00 00 00 00 00 00 XOR -->|  等待 ACK (10s超时)
  |                                    |  关闭 cam0
  |                                    |
  | Data_yinshe() x3 放豆子           |
```

## 第 5 个数字推理逻辑

1. 已知 4 个数字: 3 个正面数字 + 1 个侧面数字
2. 候选集: {0x01, 0x02, 0x03, 0x04, 0x05}
3. 从候选集中去除已知 4 个，剩余即为第 5 个
4. 5 个数字排列顺序（左->右）: `[侧面, 正面1, 正面2, 正面3, 推理第5]`

## 防抖机制

- 每个识别阶段要求连续 **3 帧** 检测结果相同才确认
- 豆子: 3 颗豆子颜色完全一致 × 3 帧
- 正面数字: 3 个数字完全一致 × 3 帧
- 侧面数字: 同一数字 × 3 帧

## STM32 端关键变量

| 变量 | 类型 | 说明 |
|------|------|------|
| `bean_color[3]` | uint8_t | 豆子颜色 (0x06/0x07/0x08) |
| `bean_flag` | uint8_t | 豆子数据就绪 (1=新数据) |
| `bean_locked` | uint8_t | 豆子锁 (收到后置1, 防覆盖) |
| `front_number[3]` | uint8_t | 正面 3 个数字 |
| `front_number_flag` | uint8_t | 正面数字就绪 |
| `number_position[5]` | uint8_t | 完整 5 个数字 (左->右) |
| `full_number_flag` | uint8_t | 完整数字就绪 |
| `k230_ack_flag` | uint8_t | K230 ACK (0x0A) 就绪 |
| `count` | uint8_t | 数字帧计数 |

## STM32 端典型调用流程

```c
// Phase 1: 发命令看豆子 -> 等 ACK -> 等数据 -> 发 ACK
k230_ack_flag = 0;
k230_write(K230_CMD_LOOK_BEAN);          // 0x02
wait_flag(&k230_ack_flag, 3000);         // 等 K230 ACK
wait_flag(&bean_flag, 25000);            // 等豆子数据
k230_write(K230_CMD_CLOSE);              // 发 ACK

// Phase 2: 发命令看正面数字 (不发数据帧, K230 内部存储)
k230_ack_flag = 0;
k230_write(K230_CMD_LOOK_NUMBER);        // 0x03
wait_flag(&k230_ack_flag, 3000);         // 等 K230 ACK (命令收到)
k230_ack_flag = 0;
wait_flag(&k230_ack_flag, 25000);        // 等 K230 ACK (识别完成)
k230_write(K230_CMD_CLOSE);              // 发 ACK

// Phase 3: 发命令看侧面数字
k230_ack_flag = 0;
k230_write(K230_CMD_LOOK_SIDE);          // 0x01
wait_flag(&k230_ack_flag, 3000);
wait_flag(&full_number_flag, 25000);
k230_write(K230_CMD_CLOSE);

// 放豆子
Data_yinshe(bean_color[0]);
Data_yinshe(bean_color[1]);
Data_yinshe(bean_color[2]);
```

## 具体调用逻辑

### STM32 端 (action.c :: action_test)

上电后 `Action_Init()` 创建 action_test 任务，按以下顺序执行：

```
1. osDelay(1000)                          // 等系统稳定

2. [Phase 1] 豆子识别
   send_cmd_and_wait_ack(0x02)            // 发 LOOK_BEAN, 等 K230 ACK (3s)
   wait_flag(&bean_flag, 25s)             // 等豆子数据帧
   // bean_color[0..2] 已就绪
   k230_write(0x06)                       // 发 ACK, K230 关闭 cam2

3. action_douzi_first()                   // 电机动作: 抓豆子 (文字占位)
   // Motor_XYZ(右44cm, 前185cm, 上35cm)  // 起始 -> 抓左边豆子
   // Motor_XYZ(左20.5cm, 不动, 不动)      // 抓中间豆子
   // Motor_XYZ(左60cm, 不动, 不动)        // 准备去放箱子

4. [Phase 2] 正面数字识别
   // 电机动作: 障碍物避让 (文字占位)
   // Motor_XYZ(不动, 后100cm, 不动)       // 障碍物避让 1
   // Motor_XYZ(右65cm, 后160cm, 不动)     // 障碍物避让 2

   send_cmd_and_wait_ack(0x03)            // 发 LOOK_NUMBER, 等 K230 ACK (3s)
   wait_flag(&k230_ack_flag, 25s)         // 等 K230 识别完成 ACK
   // 正面数字仅 K230 内部存储, STM32 不接收
   k230_write(0x06)                       // 发 ACK, K230 关闭 cam1

5. [Phase 3] 侧面数字 + 推理
   // 电机动作: 到箱子位置 (文字占位)
   // Motor_XYZ(不动, 后55cm, 不动)        // 到箱子位置

   send_cmd_and_wait_ack(0x01)            // 发 LOOK_SIDE, 等 K230 ACK (3s)
   wait_flag(&full_number_flag, 25s)      // 等完整 5 数字帧
   // number_position[0..4] 已就绪
   k230_write(0x06)                       // 发 ACK, K230 关闭 cam0
   bean_locked = 0                        // 解锁豆子锁

6. 放豆子
   Data_yinshe(bean_color[0])            // 豆子1 -> 查 number_position -> Action_x()
   Data_yinshe(bean_color[1])            // 豆子2 -> 查 number_position -> Action_x()
   Data_yinshe(bean_color[2])            // 豆子3 -> 查 number_position -> Action_x()

7. for (;;) osDelay(1000)                 // 挂起
```

### K230 端 (k230_competition.py :: __main__)

上电后顺序执行，完全被动等待 STM32 命令：

```
1. Display.init + MediaManager.init       // 初始化硬件
   yolo_det = YOLOv11App("best.kmodel")  // 加载模型 (8类)
   yolo_det.config_preprocess()           // 配置 AI2D 预处理

2. [Phase 1] 等待豆子识别命令
   wait_first_cmd_with_ready(0x02)        // 无限等, 期间每 300ms 发就绪帧 0x0B
   send_ack()                             // 发 ACK (命令收到)

   sensor = config_camera(2)              // 开 cam2
   sensor.run()

   recognize_beans(yolo_det, sensor)      // 识别循环:
     // 每帧: snapshot -> YOLO推理 -> 过滤class 5-7 -> 按x排序 -> 取前3个
     // 防抖: 连续3帧结果一致才返回
     // 返回: [0x06, 0x07, 0x08] (绿豆, 芸豆, 黄豆)

   send_frame(0x02, bean_result)          // 发豆子数据帧
   wait_for_cmd(0x06, 10s)                // 等 STM32 ACK
   close_sensor(sensor)                   // 关 cam2

3. [Phase 2] 等待正面数字识别命令
   wait_for_cmd(0x03, timeout_ms=0)       // 无限等 STM32 发 LOOK_NUMBER
   send_ack()                             // 发 ACK (命令收到)

   sensor = config_camera(1)              // 开 cam1
   sensor.run()

   front_numbers = recognize_front_numbers(yolo_det, sensor)
     // 每帧: snapshot -> YOLO推理 -> 过滤class 0-4 -> 按x排序 -> 取前3个
     // 防抖: 连续3帧结果一致才返回
     // 返回: [0x01, 0x03, 0x05] (正面3个数字, 存K230内部)

   send_ack()                             // 发 ACK (识别完成, 不发数据帧)
   wait_for_cmd(0x06, 10s)                // 等 STM32 ACK
   close_sensor(sensor)                   // 关 cam1

4. [Phase 3] 等待侧面数字识别命令
   wait_for_cmd(0x01, timeout_ms=0)       // 无限等 STM32 发 LOOK_SIDE
   send_ack()                             // 发 ACK (命令收到)

   sensor = config_camera(0)              // 开 cam0
   sensor.run()

   side_number = recognize_side_number(yolo_det, sensor)
     // 每帧: snapshot -> YOLO推理 -> 过滤class 0-4 -> 取最高置信度
     // 防抖: 连续3帧结果一致才返回
     // 返回: 0x02 (侧面1个数字)

   // 推理第5个数字
   known = [side_number] + front_numbers  // [侧面, 正1, 正2, 正3] = 4个已知
   fifth = infer_fifth(known)             // {1,2,3,4,5} - 已知4个 = 缺失的第5个
   full_result = known + [fifth]          // [侧面, 正1, 正2, 正3, 推理第5]

   send_frame(0x01, full_result)          // 发完整5数字数据帧
   wait_for_cmd(0x06, 10s)                // 等 STM32 ACK
   close_sensor(sensor)                   // 关 cam0

5. 释放模型 + Display + MediaManager      // 清理
```

### Data_yinshe 放豆子逻辑

STM32 收到完整 5 个数字后, 根据豆子颜色查找对应箱子位置:

```
number_position[5] = [侧面, 正面1, 正面2, 正面3, 推理第5]
                     例如: [0x02, 0x01, 0x03, 0x05, 0x04]

bean_color[0] = 0x06 (绿豆) -> target=2 -> 遍历 number_position 找 0x02 -> 位置1 -> Action_1()
bean_color[1] = 0x07 (芸豆) -> target=3 -> 遍历 number_position 找 0x03 -> 位置3 -> Action_3()
bean_color[2] = 0x08 (黄豆) -> target=1 -> 遍历 number_position 找 0x01 -> 位置2 -> Action_2()

颜色->目标值映射:
  绿豆 0x06 -> target=2 (放到数字2的箱子)
  芸豆 0x07 -> target=3 (放到数字3的箱子)
  黄豆 0x08 -> target=1 (放到数字1的箱子)

Action_1()~Action_5() 为 __weak 空桩, 需在 action.c 中实现实际电机动作
```
