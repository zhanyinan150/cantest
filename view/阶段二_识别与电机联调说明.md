## 三、执行时序（两端对照）

```
STM32 (action_1)                      K230 (k230_competition.py)
──────────────────────────────────────────────────────────────────
上电 → osDelay(1000ms)                 启动 → 载入 best.kmodel
                                       Phase1: 等 0x02（超时 30s）
【Phase1 豆子识别】
  发 LOOK_BEAN(0x02)      ──────►     收到 → 回 ACK(0x0A)
  等 ACK（超时 3s）        ◄──────
                                       开 Camera2 → 识别 3 颗豆（超时 20s）
  等数据帧（超时 15s）      ◄──────     发 [0x02,0,b1,b2,b3,0,0,XOR]
  → bean_color[3]
  回 CLOSE(0x06)          ──────►     关 Camera2

【抓豆动作 ≈34s】
  1/7 X+44 Y+185 Z+35   ← 唯一执行的升降
  [SERVO-SIM] servo init
  2/7 claw down [Z SKIPPED]
  [SERVO-SIM] WHITE claw GRAB
  3/7 claw up   [Z SKIPPED]
  4/7 X-20.5（中间豆）
  [SERVO-SIM] rotate axis
  5/7 claw down [Z SKIPPED]
  [SERVO-SIM] BLACK claw GRAB
  6/7 claw up   [Z SKIPPED]
  [SERVO-SIM] ready for box
  7/7 X-60（去放箱）

【放箱 + Phase2/3】
  obstacle step1: Y-100
  obstacle step2: X+65 Y-160     ← 机构到达可看正面数字的位置
  发 LOOK_NUMBER(0x03)    ──────►     收到 → 回 ACK #1
  等 ACK #1               ◄──────
                                       开 Camera1 → 识别正面 3 个数字
  等 ACK #2（超时 15s）    ◄──────     回 ACK #2（**仅 ACK，不发数据**）
  回 CLOSE(0x06)          ──────►     关 Camera1
  move to box: Y-55
  发 LOOK_SIDE(0x01)      ──────►     收到 → 回 ACK
  等 ACK                  ◄──────
                                       开 Camera0 → 识别侧面 1 个数字
                                       infer_fifth() 推理第 5 位
  等数据帧                 ◄──────     发 [0x01,0,n1..n5,XOR]
  → number_position[5]
  回 CLOSE(0x06)          ──────►     关 Camera0 → 结束

【分拣决策】
  Data_Handle1(颜色) 查表 → box 1~5
  打印 [SIM] beanN ... -> box N
任务挂起
```

### 三个关键设计点

1. **Phase1 必须在抓豆之前** —— 抓完再识别就来不及决定放哪个箱。
2. **正面数字不回传** —— Phase2 K230 只发两个 ACK，正面 3 个数字仅存在 K230 内部，
   用于 Phase3 推理第 5 位。这是唯一等两次 ACK 的阶段。
3. **第 5 个箱子靠推算** —— K230 只能看到 4 个数字（正面 3 + 侧面 1），
   第 5 个用 `{1,2,3,4,5}` 减去已知推出。脚本有两层兜底确保绝不发 `0x00`
   （`K230.c` 要求 5 字节全非零，否则不置标志 → 主机超时 → 整局失败）。

### 颜色 → 箱位映射（`Data_Handle1`）

| 豆子 | 编码 | 找数字 |
|---|---|---|
| 绿豆 GREEN | 0x06 | 2 |
| 芸豆 YUN | 0x07 | 3 |
| 黄豆 YELLOW | 0x08 | 1 |

## 五、观察要点

| 观察点 | 判断 |
|---|---|
| `[P1] Bean` 三个值 | 是否为 06/07/08 中的合法值，与实际摆放是否一致 |
| `[P3] Numbers` 五个值 | 是否全部非 0 且互不重复（1~5 各一次） |
| `[SIM] beanN -> box N` | 颜色→箱位映射是否符合预期 |
| `[ACT] N/7` 各步 | XY 实际行程与标称距离是否吻合（**轮径标定见下**） |
| 是否出现 `[RTY]` | 出现即触发重试，记录是偶发还是必现 |
| `SKIPPED: not in boxes` | 该颜色对应数字不在识别结果里，多为识别错或推理降级 |

### 安全提示

第 1 步 Z 上升 35cm 是**真实执行**的，确保 Z 轴上方有足够空间。
X/Y 全行程真实执行，首次跑建议手放在急停位置。
